# Networking Fundamentals - Level 5: 3–3.5 Year Engineer Mastery

## 1. SRE Top-Down Troubleshooting Methodology
When an external service is reported down:
1. **DNS Layer:** Verify client resolves correct CNAME/A-record (`dig +trace`).
2. **Edge / CDN Layer:** Check CloudFront / Cloudflare SSL certificate and WAF rules.
3. **Load Balancer Layer:** Check AWS ALB Target Group health metrics and access logs.
4. **Security Group / NACL Layer:** Verify inbound rules on port 80/443 and egress ephemeral port return rules.
5. **Ingress / Reverse Proxy Layer:** Check Nginx / Ingress Controller error logs for upstream drops.
6. **Container / Workload Layer:** Verify application is listening on `0.0.0.0`, not `127.0.0.1`.

## 2. Professional Interview Response: "How do you triage a 504 Gateway Timeout?"
> *"A 504 Gateway Timeout occurs when a proxy or load balancer waits for a response from the upstream application server for longer than its configured timeout threshold.
> 
> My investigation begins by checking the load balancer and proxy error logs to confirm which upstream IP timed out. Next, I inspect application metrics—specifically database query latency, thread pool saturation, and external third-party API calls. In 90% of production cases, a 504 is caused by unindexed database slow queries locking connection pools, or an unhandled timeout in downstream microservices. I correlate the incident timestamp with APM traces and slow-query logs to identify the bottleneck."*
