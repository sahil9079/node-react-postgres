# Linux Fundamentals - Level 5: 3–3.5 Year Engineer Mastery

## 1. Senior Problem-Solving & Architecture Mindset
A 3.5-year engineer does not guess; they isolate issues methodically across layers:
1. **Application Layer:** Logs, stack traces, exit codes.
2. **User Space:** Permissions, environment variables, dependencies, ulimits.
3. **Kernel / System Layer:** Inodes (`df -i`), Open FDs (`lsof`), OOM Killer (`dmesg -T`), CPU throttling.
4. **Hardware / Storage Layer:** Disk I/O bottlenecks (`iostat`), Network socket exhaustion (`netstat -ant | grep TIME_WAIT`).

## 2. Production Incident Walkthrough: High Load & Unresponsive Server
* **Scenario:** Server load average is 24 on an 8-core CPU. CPU utilization is only 15%.
* **Engineering Analysis:** High load with low CPU utilization indicates processes stuck in **Uninterruptible Sleep (D state)** waiting for I/O (Disk or NFS).
* **Triage Commands:**
  ```bash
  # Check process states (Look for 'D' status)
  ps -eo pid,user,state,cmd | awk '$3 ~ /D/'
  
  # Check I/O wait and Disk queue
  vmstat 1 5    # Column 'b' (blocked processes) and 'wa' (I/O wait CPU %)
  iostat -xz 1  # Check %util and await columns for disk saturation
  ```

## 3. Professional English Interview Explanation
> *"In Linux administration, I focus on resource isolation, kernel performance tuning, and rapid diagnostics. For instance, when troubleshooting server degradation, I analyze metrics using the USE method (Utilization, Saturation, Errors). I utilize tools like `vmstat`, `iostat`, and `strace` to identify whether bottlenecks stem from CPU starvation, memory paging, I/O wait, or socket exhaustion. In production, I enforce least privilege using strict user permissions, configure custom systemd services with auto-restart policies, and manage ulimits to ensure applications can scale without hitting file descriptor boundaries."*
