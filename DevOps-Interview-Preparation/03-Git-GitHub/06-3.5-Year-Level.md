# Git & GitHub - Level 5: 3–3.5 Year Engineer Mastery

## 1. Resolving Merge Conflicts & History Recovery
* When an accidental `git reset --hard` deletes uncommitted or unpushed work:
  ```bash
  # Recover lost commits using the Reflog
  git reflog
  # Find commit hash before reset (e.g. HEAD@{2})
  git checkout -b recovered_branch HEAD@{2}
  ```

## 2. Interview Response: "When do you use `git rebase` vs `git merge`?"
> *"In our team workflow, I use `git rebase` locally on my private feature branch before opening a Pull Request to synchronize with `main` and maintain a clean, linear commit history. However, on public, shared branches like `main` or `release`, I strictly use Pull Request merges or squash-merges. I never rebase shared branches because rebasing rewrites commit hashes, which breaks git history for other engineers collaborating on that branch."*
