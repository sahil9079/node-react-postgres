## 1. Troubleshooting AWS Networking: EC2 in Private Subnet Cannot Pull ECR Images
* **Symptoms:** Pods on EKS worker nodes fail with `ImagePullBackOff` or timeout connecting to `*.dkr.ecr.us-east-1.amazonaws.com`.
* **Root Cause Analysis:**
  1. Node is in a Private Subnet, but Route Table lacks a route (`0.0.0.0/0 -> NAT Gateway ID`).
  2. NAT Gateway in Public Subnet lacks an Elastic IP (EIP) or public subnet lacks route to Internet Gateway.
  3. Alternatively, missing AWS VPC Endpoints for ECR (`com.amazonaws.region.ecr.api`, `com.amazonaws.region.ecr.dkr`, and S3 Gateway Endpoint).

## 2. Professional Interview Explanation
> *"In our AWS architecture, security and high availability are designed into the foundational VPC layout. We deploy our workloads in private subnets across three Availability Zones, fronted by an Application Load Balancer in public subnets. We manage access strictly using IAM Roles and Policies following least privilege, enforcing IRSA for all Kubernetes microservices. To optimize data transfer costs and enhance security, we utilize VPC Endpoints for S3 and ECR traffic instead of routing through NAT Gateways."*
